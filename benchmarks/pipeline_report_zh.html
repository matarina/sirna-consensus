摘要

流水线核心。 输入是一条转录本 FASTA。外部生成器（siRNAdesigner、siRNAforge）各自枚举候选，包内只负责把它们的输出归一化、定位到转录本坐标，并按“位点”（start + length）归并投票；过滤在投票之后执行；排序输出 Top-K。SIREN 是评估器而非生成器，只提供证据，不投设计票。OligoFormer 冻结打分器与 Bowtie/Ensembl 116 筛查分别提供效力排序与计算特异性证据，但都不是设计票，也不构成湿实验结论。

当前证据。 在暴露的 Huesken 开发集上，冻结打分器具有真实区分度（AUROC 0.827、AP 0.82、Spearman ρ 0.66；十分位命中率从 5.2% 升到 92.3%，基线 50.2%）。质量融合在开发集达到 92.8% 的基因加权 Top-5 精确率，冻结模型为 90.4%；配对增益 +2.4 个百分点，95% CI [-0.8, +5.6]，未达到预设的 +10 个百分点门槛。最终 weight-independent 留出集实际可评估 399 条记录 / 10 个标签 / 5 项研究，策略与模型在 9 个共享基因上均为 +0.0 个百分点。AREG 真实运行把 1,246 条原始命中收敛为 204 个位点、59 个双生成器共识位点、34 条过滤后候选、10 条最终 Top-10；但未提供转录组，特异性状态全部为 input_only。

尚未成立。 没有独立效力验证；没有证据表明共识/融合优于冻结模型；没有全转录组特异性结论。留出集是 weight-independent 但 upstream-evaluation-exposed；近重复序列、异构体与基因同义词未审计。当前报告应作为研究级设计辅助，而不是临床或实验证据。

1. 研究问题与设计原则

临床前 siRNA 的核心决策不是“给每条候选一个绝对分数”，而是在固定合成预算 k 下，前 k 条中实际有效的比例。若只比较绝对分数，不同工具、不同候选覆盖率和不同面板完成度会制造虚假优势。因此本流水线把主终点定义为基因加权 Top-5 实测精确率，同时报告完成度、填充率与候选覆盖率；只有完整面板的基因才进入数值门槛。

第二个原则是“证据分层”。公开 siRNA 数据集大多与打分模型的开发集重叠，必须区分检查点训练暴露（改变权重）与上游评估暴露（可能影响模型选择/早停）。前者使数据只能作为诊断；后者使数据 weight-independent 但不 fully independent。报告明确标注每一层，而不是把“留出”当作“独立”。

第三个原则是“共识在位点层面，不在字符串层面”。不同工具对同一双链给出不同长度、偏移和悬垂；精确字符串交集会系统性丢弃真实一致。包内不做本地窗口枚举，只把外部工具的输出放到同一转录本坐标轴上，以不同生成器工具的票数决定候选。

2. 全流程总览

深蓝 = 投设计票的生成器；虚线 = 评估器/打分器，仅提供证据；青绿 = 核心共识逻辑；琥珀 = 产物；红色 = 发布门槛/标签盲评估。

3. 数据与证据层级

当前基准的主数据源是 Figshare 的 siRNA 效力快照（DOI 10.6084/m9.figshare.25908841.v1），共 3,544 条记录、7 项研究。开发集是 Huesken 2005 子集：25 个克隆构建体、1,941 条全长引导链，使用原始构建体坐标与原始归一化活性；0.7 是操作阈值，不是生物学定义。

最终留出集来自六项非 Huesken 研究：1,113 条记录、12 个源标签。审计规则是“精确 19-nt 反义核心”与训练集、开发集、上游评估集比对；Huesken 属训练暴露；六项非 Huesken 研究不共享训练/开发分子，所以是 weight-independent，但全部是 upstream-evaluation-exposed。代码明确记录 fully_independent_available = false。

两个终点不能混用：开发集使用归一化报告活性（阈值 0.7）；留出集使用 percent inhibition（阈值 70）。数据库的百分比抑制字段不能直接当作内源性敲低百分比。

4. 各阶段详解（通俗版 + 技术要点）

一句话版本： 把一条 mRNA 序列交给几个独立设计工具，让它们各自提候选；把候选放到同一张转录本地图上，按“同一位置、同一长度”归并投票；先投票再过滤；最后用冻结打分器排序、用 Bowtie 查脱靶，并把规则和数据先封存再评估。

七步直觉：

  1. 一张图纸： 输入是一条 FASTA 序列，不是基因名；包内不自己找窗口，工具负责枚举。
  2. 三位设计师： siRNAdesigner 和 siRNAforge 是“投设计票”的生成器；SIREN 是“评审”，只给证据，不投票。
  3. 统一坐标： 每个工具的输出长度、偏移、悬垂都不同；先换算成转录本上的 1-based 闭区间，再拆出结合核心、引导链、过客链、悬垂。
  4. 按位点投票： 不比较整条字符串，而是看候选是否落在同一个“起点 + 长度”的窗口；只有不同生成器都提出，才算共识票。
  5. 先投票、后过滤： 先看哪些位点被多个工具支持，再用 GC、同聚物、5′ 端碱基等筛掉不合格者。
  6. 排序不是测敲低： 冻结打分器给的是排序分数，不是敲低百分比；质量融合是“模型分 + 工具支持 + 序列质量”的加权。
  7. 筛查与封存： Bowtie 查其他基因的近似命中；没有转录组就只能标 input_only。最后把数据、模型、切分、预测写进冻结锁，先验锁再读标签。

4.1 输入与校验

通俗地说，这就像把一条 mRNA 当成一张地图：包内只负责在地图上标出外部工具给出的候选位置，不自己沿着地图逐格找窗口。输入记录 SHA-256，所有下游产物都带来源哈希。代价是：如果外部工具的坐标或格式解析出错，错误会进入归一化阶段，而不是被包内“猜测”修复。

4.2 外部工具与角色

通俗地说，三个工具像三位设计师：siRNAdesigner 和 siRNAforge 各自提出设计稿并“投票”；SIREN 只是评审，能说“这条可以/这条不行”，但不能替设计师提出新稿。siRNAdesigner 的 19-bp staggered duplex 保留原始 21-nt 两条链；siRNAforge 以 --modifications none --overhang '' 运行，遇到不支持的化学修饰会拒绝并记录，而不是截断。同一工具的多个命中不重复计票。

在 AREG 实例中：siRNAdesigner 80 条命中、siRNAforge 559 条命中、SIREN 607 条评估器枚举命中。三者合计 1,246 条原始命中。

4.3 归一化与定位

通俗地说，工具输出的坐标像不同人写的地址：有人写“908–928”，有人写“907–927”，还有人把悬垂单独写在末尾。包内先把它们统一成转录本上的 1-based 闭区间，再把结合核心、原始引导链/过客链、3′ 悬垂拆成独立字段；归并使用 offset tolerance = 2，即允许相邻一两个碱基的偏移。归一化不改变分子身份：重复位点、无效坐标、未知过客链都显式记录或拒绝，不静默合并。

4.4 位点级共识

通俗地说，投票不是比“整条字符串是否一模一样”，而是看不同工具是否落在同一个“起点 + 长度”的窗口。比如一个工具说 908–928，另一个说 908–928 但悬垂写法不同，仍算同一站点；如果只是相邻位置或长度差一位，就按 offset tolerance 归并。默认 min_votes=2，单票（singleton）被排除；因此共识 Top-K 可能为空，这是设计选择，不是错误。若工具给出不同分子，包不会强行把它们视为同一候选。

4.5 过滤

通俗地说，过滤器像筛子：先把多个工具都支持的位点挑出来，再用硬规则筛掉明显不合格的序列，而不是先筛再投票。硬过滤包括 GC 窗口 0.3–0.55、最长同聚物 ≤4、引导链 5′ 端非 A/U；软标记包括种子区 GC 偏低、sense 链 3′ 端非 A/U。软标记只告警，不淘汰。AREG 中 25 条候选被硬过滤淘汰，34 条进入排序。

4.6 排序与 Top-K

通俗地说，排序像“加权投票”：模型分数是主裁判分，工具支持和序列质量是辅助分。native 分数先转换成同格式内的 midrank 百分位；fusion 平均模型百分位与 native 百分位；support 用 0.8 模型 + 0.2 精确生成器支持；quality 用 0.8 模型 + 0.1 native + 0.1 序列质量。模型缺失时生成单独的 native 回退面板，而不是把“缺失”当“无效”。排序按分子 ID 与位置打破平局，面板选择不同引导链，并可选 30-nt 间距。

4.7 冻结效力打分器

通俗地说，打分器像一位只给“名次”的裁判：它能说这条比那条更可能有效，但它的分数不是“敲低 80%”这样的实验读数。OligoFormer 使用本地哈希固定的检查点，eval 模式、batch size 1、无拟合；输出是未标定的排序分数。模型缺失或格式不支持时不截断候选；支持记录的 19-nt 反义核心，原始悬垂仍附着在候选上。开发策略 benchmarks/results/selection_policy.json 只用于开发集，不是独立验证策略。

4.8 特异性筛查

通俗地说，筛查像“查重”：拿每条引导链去对照整个 cDNA 参考库，看看它是否会在别的基因上精确或几乎精确地命中。筛查使用固定 Ensembl release 116 cDNA 与 Bowtie 1.3.1 索引；规则是检查所有结合区域命中，允许最多两个错配；其他基因的 exact/one-mismatch 命中排除该引导链；需要目标基因的 exact 命中；two-mismatch 与 full-cDNA seed 计数只作提示。参考清单哈希不匹配、映射缺失或执行失败会使候选保持未验证状态，而不是被当作“干净”。AREG 未提供转录组，因此全部 59 条候选为 input_only，不能主张脱靶结论。

4.9 冻结与最终评估

通俗地说，冻结像先把规则和证据装进一个封条：数据、代码、模型、切分、协议、种子与预测在读取标签前写入 freeze lock，之后才允许看测量结果。选择阶段标签盲；最终评估先验证锁，再读取测量表，并要求 cohort manifest 中 checkpoint_training_audit=verified 且 independent_holdout_eligible=true。冻结锁不覆盖；留出集在查看结果后不得重切。开发锁由 gen_development_freeze.py 重建，CI 与 verify 脚本检查现有锁。

开发集最优策略 quality 相对冻结模型的配对差异：k=5 为 +2.4 pt，95% CI [-0.8, +5.6]；k=10 为 +1.2 pt，95% CI [-0.8, +3.6]。两个区间都跨 0，且远低于 +10 pt 门槛，数值判据未通过。

5.4 阈值敏感性

0.7 的阈值是人为操作线，不是生物学常数。改变阈值会显著改变绝对精确率，而模型的相对区分度仍然存在；在 0.9 时 quality 相对 model 的优势归零。因此 0.7 那一行的 92.8% 不能当作阈值无关的结论。

6. 数据泄漏与可辩护性

关键判断： 基准对暴露是诚实的，但没有消除泄漏。开发集是检查点训练暴露；留出集是 weight-independent，但所有留出研究都 upstream-evaluation-exposed，fully_independent_available = false。审计只做精确 19-nt 反义核心匹配，不检查坐标、异构体、近重复序列；基因同义词未合并（Firefly luciferase 与 FireflyLuc），并且包含 reporter/单构建体标签。留出集很小，+0.0 pt 不能证明优越性。可辩护的结论是：打分器在开发集上有信息量，流水线可复现，共识/融合优于模型的证据不足。

更具体地说，泄漏有三层：

  • 训练泄漏： Huesken 分子进入 OligoFormer 训练（Hu.csv），所以开发集数字是 in-sample 诊断。
  • 模型选择泄漏： 上游在 Mix/Taka 上做评估并选择 epoch/超参数；holdout 分子未改变权重，但影响了模型选择。代码明确记录“selects epochs on Mix”，因此 weight-independent 不等于 fully independent。
  • 匹配粒度泄漏： 精确 19-mer 只捕捉完全相同的核心；1–2 nt 差异、反向互补、异构体、同义基因都可能逃过审计。近重复序列仍可能让模型“见过”同一基序。

此外，策略是在开发集上选出的，再用于留出集比较，存在 winner’s curse；多个分层样本不足，Reynolds 的 7 个配对基因仍然零差异；17 个置换对比的最小 p 值是诊断性的，未充分处理多重比较。siRNAforge 与 exact consensus 在该 duplex-format 队列中没有完整面板，siRNAdesigner 只覆盖 15/25 个基因，因此方法间不是同覆盖率的公平比较。

可以支持的结论

冻结打分器在暴露开发集上有真实排序信息（AUROC 0.827、AP 0.82、ρ 0.66；十分位 5.2%→92.3%）。归一化、位点归并、冻结锁与标签盲评估可复现。位点级共识是处理异构工具输出的正确抽象。

不能支持的结论

独立效力验证；共识/融合优于冻结模型；AREG 的全转录组特异性；从 reporter/单构建体留出集外推到人类内源性靶基因；任何湿实验敲低结论。

7. 局限与改进方向

当前报告的主要局限是：留出集只有 399 条可评估记录、10 个标签、5 项研究；每分子只有一个构建体；阈值 0.7/70 是操作线；模型输出未标定；原生生成器证据覆盖 59%；多个分层配对基因不足；上游评估暴露无法消除；近重复/异构体/同义词未审计。要提升可辩护性，应：(1) 用 --criterion fully 寻找或补充完全无上游评估暴露的队列；(2) 审计 Hamming ≤2、反向互补、异构体与基因同义词；(3) 将 reporter 构建体与内源性人类靶基因分开；(4) 预注册、冻结、增加基因与构建体数量并做功效分析；(5) 对多层比较做多重校正；(6) 冻结检查点，避免上游早停暴露。

9. 结论

sirna-consensus v1.1.0 提供了一个可复现、可审计的位点级共识设计流水线：外部生成器投票，包内归一化与排序，冻结打分器与独立筛查提供证据而非设计票。当前证据支持“冻结打分器具有排序信息”和“流水线可复现”，但不支持“共识/融合优于模型”或“独立效力验证”。开发集 +2.4 pt（CI 跨 0）与最终留出集 +0.0 pt（independent_validation_passed=false）共同说明：这是研究级设计辅助，仍需独立实验验证。
